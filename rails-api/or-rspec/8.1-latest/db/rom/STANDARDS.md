# ROM migrations

`db/rom/migrate` holds the `rom-sql` (Sequel) migrations that create the app's tables. They are separate from `db/migrate` so Active Record never loads them (Active Record is installed only for Solid Queue, Solid Cache, and Solid Cable).

## Rules

- Run migrations with `bin/rails rom:migrate` (`VERSION=<n>` migrates to that version, `VERSION=0` reverts all). `bin/rails rom:status` shows whether any are pending. Versions are kept in `rom_schema_migrations`, not Active Record's `schema_migrations`.
- Create tables with `ROM::SQL.migration` and `change` blocks. Use `up`/`down` only when `change` cannot reverse the operation.
- One table per migration, named `YYYYMMDDHHMMSS_create_<table>.rb`.
- Table names are plural snake_case. Columns are snake_case.
- Every table has `id`, `created_at`, and `updated_at`, in that order, using the formats below.
- Declare constraints in the database: `null: false` by default, foreign keys, unique indexes. Do not rely on app-level validation alone.
- Index every foreign key column.
- Set `on_delete` explicitly on every foreign key. Default to `:restrict`.
- Foreign keys to another table's id use `type: :uuid`.
- Name foreign key columns for the role, not the table (e.g. `owner_id`, not `user_id`, when the user is an owner).
- Do not edit a migration that has run in any shared environment. Add a new one.

## Column formats

| Attribute | Definition |
|-----------|------------|
| `id` | `column :id, :uuid, null: false, default: Sequel.function(:gen_random_uuid), primary_key: true`. UUID v4, generated by Postgres. |
| `created_at` | `column :created_at, :timestamptz, null: false, default: Sequel::CURRENT_TIMESTAMP` |
| `updated_at` | `column :updated_at, :timestamptz, null: false, default: Sequel::CURRENT_TIMESTAMP` |

All date and time attributes are `timestamptz` (stored as UTC). Never `timestamp` without time zone.

There is no database trigger. Repos set both timestamps with the shared concern `app/repos/concerns/timestamped.rb`.
