# Repos

ROM repositories. The persistence boundary for the app.

## Rules

- One `ROM::Repository::Root` per aggregate, rooted on its relation.
- Only services call repos. Controllers and jobs never do.
- Return structs (`app/models`), never hashes.
- Wrap multi-write operations in a transaction inside the repo method.
- Name repos `<Aggregate>Repo` and set `struct_namespace Object` so rows map to the structs in `app/models`.
- CRUD methods: `find` (nil when missing), `find!` (raises), `all`, `create`, `update`, `delete`. `update` and `delete` return the record, or nil when the id does not exist.
- Always order `all` and list queries.
- Set `created_at` and `updated_at` by including `Timestamped` (`app/repos/concerns/timestamped.rb`). Use `with_create_timestamps` and `with_update_timestamps` on every write. Callers cannot set them.
- Ids are generated by the database. Include `GeneratedId` (`app/repos/concerns/generated_id.rb`) and wrap attributes in `without_id` on every create and update. ROM does not strip a caller-supplied `id` itself.
- Include `ReaderWriter` (`app/repos/concerns/reader_writer.rb`). Build repos with `UserRepo.reader` for reads and `UserRepo.writer` for writes. Do not call `new` with the container. Both use the same database for now.
- Shared repo code goes in `app/repos/concerns`.
- Comment only above non-CRUD methods. Do not comment `find`, `find!`, `all`, `create`, `update`, or `delete`.
- Referential rules rely on foreign keys, not check-then-insert. Rescue `ROM::SQL::ForeignKeyConstraintError` and raise a repo-level error (e.g. `AccountRepo::OwnerNotFound`).
